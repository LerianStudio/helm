# plugin-bc-correios Helm Chart

## Chart Contract

- Chart type: `single-service`
- Required secrets: `bc-correios.secrets.RABBITMQ_PASS`, `RABBITMQ_URL`, and `ENCRYPTION_KEY`, plus `RABBITMQ_ERLANG_COOKIE` while the bundled RabbitMQ is enabled (the default). The PostgreSQL password is **not** operator-provided with the bundled subchart: the Bitnami `postgresql` subchart auto-generates it into the `<release>-postgresql` Secret (key `password`) and the app reads it via `secretKeyRef`. Set `bc-correios.secrets.POSTGRES_PASSWORD` only for an external PostgreSQL (`postgresql.external=true`) without `postgresql.auth.existingSecret`.
- Dependency notes: Uses local PostgreSQL, RabbitMQ, and Valkey dependency charts (plus an inline SeaweedFS deployment) unless external services are configured. The in-cluster PostgreSQL, RabbitMQ, Valkey, and object-storage hosts are derived automatically (collapse-aware), so any release name works; set the corresponding `bc-correios.configmap.*_HOST`/`CACHE_ADDR`/`OBJECT_STORAGE_ENDPOINT` only when pointing at external/overridden endpoints.
- Production overrides: Provide production database, RabbitMQ, and encryption secrets through chart secrets or an existing Secret where supported; override image tags, ingress, resources, and persistence.
- Source/license: Source is in `github.com/LerianStudio/helm`; license is Elastic License 2.0.

Helm chart for deploying the BC Correios plugin service.

## Install

```sh
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo add groundhog2k https://groundhog2k.github.io/helm-charts
helm dependency build ./charts/plugin-bc-correios
helm upgrade --install plugin-bc-correios ./charts/plugin-bc-correios \
  --namespace plugin-bc-correios --create-namespace \
  --values ./charts/plugin-bc-correios/values-template.yaml
```

## Required Configuration

- Apply the database migrations before the first start and after each image upgrade. The chart does not run them, and the application does not run them at startup. The image ships them in golang-migrate format under `/migrations`.
- The application image `ghcr.io/lerianstudio/plugin-bc-correios` is private: set `bc-correios.imagePullSecrets` to a Secret that can pull it.
- Set the required RabbitMQ secrets (`RABBITMQ_PASS`, `RABBITMQ_URL`, and `RABBITMQ_ERLANG_COOKIE` with the bundled RabbitMQ) and `ENCRYPTION_KEY` before install. The bundled PostgreSQL and Valkey passwords are auto-generated by their subcharts and read via `secretKeyRef`; to pin them, set `postgresql.auth.*` / `valkey.auth.*` or supply `postgresql.auth.existingSecret` / `valkey.auth.existingSecret`. For an external Valkey with authentication, set `bc-correios.secrets.CACHE_PASSWORD`, or `valkey.auth.existingSecret` (with `valkey.auth.existingSecretPasswordKey`, default `valkey-password`), which takes precedence and is read via `secretKeyRef`.
- The bundled RabbitMQ imports its definitions file at boot, and the chart adds the application account to it: user `RABBITMQ_USER`, password `RABBITMQ_PASS`, full permissions on vhost `/`. Make `RABBITMQ_URL` use that account. The broker reads the file only at boot, so after changing `RABBITMQ_USER` or `RABBITMQ_PASS` on an installed release, restart it with `kubectl rollout restart statefulset/<release>-rabbitmq` before the app pods restart. With `bc-correios.useExistingSecret` the chart does not know the password, so create the account yourself. The bundled broker's data volume is an `emptyDir` (`rabbitmq.persistence.size` is not a key of the subchart and has no effect); set `rabbitmq.storage.requestedSize` on a new install to keep data across pod restarts. With an external broker, create the account yourself: the RabbitMQ bootstrap Job (`global.externalRabbitmqDefinitions.enabled`) only imports exchanges, queues, and bindings; it does not create users.
- The default install has plugin auth on: `PLUGIN_AUTH_ENABLED: "true"`, authorizing requests against the Access Manager at `PLUGIN_AUTH_ADDRESS` (rendered as the app's `PLUGIN_AUTH_HOST`; default `http://plugin-access-manager-auth.midaz-plugins.svc.cluster.local:4000`). `PLUGIN_AUTH_HOST` in `bc-correios.configmap` takes precedence over `PLUGIN_AUTH_ADDRESS`. With `bc-correios.useExistingSecret`, the chart renders no `PLUGIN_AUTH_HOST` unless `bc-correios.configmap.PLUGIN_AUTH_HOST` is set, so put it in that Secret or in `configmap`. `ENV_NAME` sets the libraries' environment (auth-client log format, lib-commons security tier); `APP_ENV` drives the app's own validation and the chart renders it as `production` unless you set it. In `production` the app requires `LICENSE_KEY` and `PLUGIN_AUTH_ENABLED: "true"`, and refuses `POSTGRES_SSLMODE: "disable"`, `ALLOWED_ORIGINS` empty or `*`, and an `ENCRYPTION_KEY` that is not exactly 32 bytes; the chart refuses to render `LICENSE_KEY` empty, `POSTGRES_SSLMODE: "disable"` and `ALLOWED_ORIGINS` empty or `*` in that case. For a development install set `APP_ENV: "development"`, which skips these checks and accepts plugin auth off.
- Review `bc-correios.configmap` for service URLs, telemetry, and plugin runtime settings.
- Prefer `bc-correios.useExistingSecret` when production secrets are managed outside Helm. With the bundled RabbitMQ, also set `rabbitmq.authentication.existingSecret` to that Secret and include `RABBITMQ_ERLANG_COOKIE` in it.

# Matcher Helm Chart

## Chart Contract

- Chart type: `multi-component`
- Required secrets: `matcher.secrets.RABBITMQ_PASSWORD` (install fails loud if unset, unless `matcher.useExistingSecret` is enabled). The PostgreSQL primary/replica and Valkey passwords are **single-sourced from their Bitnami subchart Secrets** — `matcher` reads them at runtime from `<release>-postgresql` (keys `password`, `replication-password`) and `<release>-valkey` (key `valkey-password`), so they are not stored in the app Secret. Only set `matcher.secrets.POSTGRES_PASSWORD`, `POSTGRES_REPLICA_PASSWORD`, and `REDIS_PASSWORD` when pointing at **external** infra without an `existingSecret`. `RABBITMQ_PASSWORD` remains operator-provided (see Known limitations). Production database and messaging credentials must not be committed in values files.
- Dependency notes: Uses local PostgreSQL, Valkey, and RabbitMQ dependency charts unless external services are configured.
- Production overrides: Provide production credentials through chart secrets or existing dependency Secrets where supported; override image tags, ingress, resources, and persistence.
- Source/license: Chart is maintained in `github.com/LerianStudio/helm` (`charts/matcher`); the Matcher application source is in `github.com/LerianStudio/matcher`.

### Release name

The PostgreSQL, Valkey, and RabbitMQ hosts (`POSTGRES_HOST`, `POSTGRES_REPLICA_HOST`, `REDIS_HOST`, `RABBITMQ_HOST`, `RABBITMQ_HEALTH_URL`) default to the subchart service names resolved collapse-aware via `common.names.dependency.fullname`, and the single-source secret references resolve to `<release>-postgresql` and `<release>-valkey` the same way — so all follow any release name (and `fullnameOverride`) automatically. The object-storage endpoint (`matcher-seaweedfs`) remains a literal carrying a `matcher-` prefix (SeaweedFS is not a dependency of this chart); installing it under a different name requires overriding `matcher.configmap.OBJECT_STORAGE_ENDPOINT` accordingly.

### Known limitations

- **RabbitMQ is not yet single-sourced.** The matcher user is provisioned from `matcher.secrets.RABBITMQ_PASSWORD`: for the bundled broker the value is injected into the imported load definitions (no static `password_hash` is committed), and for external RabbitMQ the bootstrap Job reconciles it via the management API. The value remains operator-provided (not generated by a subchart); rendering fails loud when it is empty. The only exception is `matcher.useExistingSecret: true`, which skips the app Secret (and its validation) entirely — in that case the load definitions import the matcher user without credentials, and the user cannot log in until the password is provisioned on the broker out-of-band. Single-sourcing RabbitMQ is a tracked follow-up.

Source code can be found here:
* https://github.com/LerianStudio/helm/tree/main/charts/matcher
* https://github.com/LerianStudio/matcher

This helm chart installs [Matcher](https://github.com/LerianStudio/matcher), a transaction reconciliation engine for the Lerian Studio ecosystem.

## Install Matcher Helm Chart:

To install Matcher using Helm, run the following command:

```console
$ helm install matcher oci://ghcr.io/lerianstudio/matcher-helm --version 4.0.0 -n matcher --create-namespace \
    --set matcher.configmap.DEPLOYMENT_MODE=byoc
```

This will create a new namespace called matcher if it doesn't already exist and deploy the Matcher Helm chart.

For install profiles, external dependencies, validation and known errors, see the install runbook: [English](docs/00-getting-start.en.md) | [Português](docs/00-getting-start.md).

After installation, you can verify that the release was successful by listing the Helm releases in the matcher namespace:

```console
$ helm list -n matcher
```

## Configuring Ingress for Different Controllers

The Matcher Helm Chart supports different Ingress Controllers for exposing services when necessary.

### NGINX Ingress Controller
To use the **NGINX Ingress Controller**, configure the `values.yaml` as follows:

```yaml
matcher:
  ingress:
    enabled: true
    className: "nginx"
    annotations: {}
    hosts:
      - host: matcher.example.com
        paths:
          - path: /
            pathType: Prefix
    tls:
      - secretName: matcher-tls
        hosts:
          - matcher.example.com
```

### Detached migrations (`matcher-migrations`)

Optional ArgoCD **PreSync** Secret + Job that applies the schema (up-only, single-tenant) **before** the app Deployment. matcher v3+ is detached: it refuses to boot against an unmigrated DB, and the app image ships no migration binary. Disabled by default. With the bundled PostgreSQL the Job reads the password from the subchart Secret (`<release>-postgresql`, key `password`), like the app. With external PostgreSQL it needs an operator-provided password or `matcher.useExistingSecret` pointing at a pre-created Secret. **Do not** run this with `MULTI_TENANT_ENABLED=true` (the runner refuses it; the Tenant Manager owns tenant DB migrations).

| Parameter | Description | Default Value |
|---|---|---|
| `migrations.enabled` | Enable the detached migration PreSync Job. | `false` |
| `migrations.image.repository` | Migration runner image. | `"ghcr.io/lerianstudio/matcher-migrations"` |
| `migrations.image.tag` | Migration image tag. Empty → falls back to `matcher.image.tag`. | `""` |
| `migrations.image.pullPolicy` | Image pull policy. | `"IfNotPresent"` |
| `migrations.imagePullSecrets` | Pull secrets for the migration image. | `[]` |
| `migrations.waitImage` | Image for the TCP-wait initContainer. | `busybox` |
| `migrations.postgres.{host,port,user,database,sslMode}` | Postgres connection. Empty fields fall back to `matcher.configmap.POSTGRES_*` (host derives from the postgresql subchart). | `""` |
| `migrations.postgres.password` | Password for the PreSync Secret (external PostgreSQL only). Empty → `matcher.secrets.POSTGRES_PASSWORD`. Ignored with the bundled PostgreSQL (the Job reads the subchart Secret) and when `matcher.useExistingSecret=true` (Job reads the existing Secret). | `""` |
| `migrations.backoffLimit` / `migrations.activeDeadlineSeconds` / `migrations.ttlSecondsAfterFinished` | Job retry / deadline / TTL. | `3` / `600` / `600` |
| `migrations.resources.*` | CPU/Memory requests/limits. | See `values.yaml` |

## Upgrade Notes

### 3.1.0

- **The MCP component is gone.** `templates/mcp/`, the `mcp:` values block and the `matcher-mcp` image are removed. A values file that still sets `mcp` renders without it, but delete the block anyway. The `matcher-mcp` Deployment, Service, Ingress, ConfigMap and Secret leave the cluster only when the sync prunes; with prune off, delete them by hand.

### 3.0.0

- **The UI component is gone.** The Matcher console now ships inside product-console, which reaches the Matcher API server-side through `MATCHER_BASE_PATH` on the product-console chart. `templates/ui/`, the `ui:` values block and the `matcher-ui` image are removed, and the render **fails** while a values file still sets `ui`.
- **The `/agent` Copilot route on the UI host is gone** with `ui.copilotIngress`.
- **Move the public API host to `matcher.ingress` first.** Environments that served the API through the UI ingress (`ui.ingress.apiPaths` `/v1` and `/system`) lose that host on upgrade. Carry the host, its TLS and the `proxy-body-size: 20m` annotation over:

```yaml
matcher:
  ingress:
    enabled: true
    className: nginx
    annotations:
      nginx.ingress.kubernetes.io/proxy-body-size: 20m
    hosts:
      - host: matcher.example.com
        paths:
          - path: /v1
            pathType: Prefix
          - path: /system
            pathType: Prefix
    tls:
      - hosts: [matcher.example.com]
        secretName: matcher-tls
```

### 2.0.0

- **`matcher.configmap.DEPLOYMENT_MODE` is required** (`saas` | `byoc` | `local`) and the chart ships no default. Earlier charts never set it, so every release booted in `local`, the development posture. Every release must now set it; the render fails otherwise.
- **`SWAGGER_HOST` / `SWAGGER_SCHEMES` are gone.** They are no longer emitted nor read as a fallback; set `PUBLIC_BASE_HOST` / `PUBLIC_BASE_SCHEMES` instead. `SWAGGER_ENABLED` is unchanged.

```yaml
matcher:
  configmap:
    DEPLOYMENT_MODE: "byoc"
```

| Variable | Description | Default Value |
|---|---|---|
| `DEPLOYMENT_MODE` | Deployment posture: `saas` (Lerian-hosted multi-tenant), `byoc` (client-hosted) or `local` (development). The render fails when it is unset. | required, no default |

| `LOG_LEVEL` | Log level. | `"info"` |
| `SERVER_ADDRESS` | Server address. | `":8080"` |
| `HTTP_BODY_LIMIT_BYTES` | HTTP body limit in bytes. | `"104857600"` |

| `POSTGRES_REPLICA_PASSWORD` | PostgreSQL replica password. Single-sourced from `<release>-postgresql` (key `replication-password`) for internal PostgreSQL. Set only for external PostgreSQL without an `existingSecret`. | `""` |

| `OBJECT_STORAGE_SECRET_ACCESS_KEY` | Object storage secret key. | `""` |

### Licence file (offline alternative to `LICENSE_KEY`)

| Value | Description | Default |
|---|---|---|
| `matcher.licenseFile.existingSecret` | Operator-created Secret holding the signed licence file under the key `license.lic`. Mounted read-only as a **directory** (never a `subPath`) at `/etc/lerian/license` on the app and the migration Job. File mode needs an image on lib-license-go v5. | `""` |

The migration Job reads `LICENSE_KEY` (`optional: true`) from `matcher.existingSecretName` when `useExistingSecret` is true, else from the `<fullname>-license-hook` PreSync Secret the chart renders when the key comes from values (`secrets`, `extraEnvVars` or `configmap`). In file mode the licence Secret must exist before the sync: the PreSync Job mounts it.

## External Dependencies

To use external dependencies instead of the bundled ones, disable the internal dependencies and configure the external connection settings:

```yaml
# Disable internal PostgreSQL
postgresql:
  enabled: false
  external: true

# Configure external PostgreSQL via configmap
matcher:
  configmap:
    POSTGRES_HOST: "external-postgres.example.com"
    POSTGRES_PORT: "5432"
```

# plugin-bc-correios Helm Chart

## Chart Contract

- Chart type: `single-service`
- Required secrets: `bc-correios.secrets.ENCRYPTION_KEY` and the license (`bc-correios.configmap.LICENSE_KEY`, or `LICENSE_KEY` in the existing Secret). The PostgreSQL password is **not** operator-provided with the bundled subchart: the Bitnami `postgresql` subchart auto-generates it into the `<release>-postgresql` Secret (key `password`) and the app reads it via `secretKeyRef`. Set `bc-correios.secrets.POSTGRES_PASSWORD` only for an external PostgreSQL (`postgresql.external=true`) without `postgresql.auth.existingSecret`.
- Dependency notes: Uses local PostgreSQL and Valkey dependency charts (plus an inline SeaweedFS deployment) unless external services are configured. The streaming broker is always external. The in-cluster PostgreSQL, Valkey, and object-storage hosts are derived automatically (collapse-aware), so any release name works; set the corresponding `bc-correios.configmap.POSTGRES_HOST`/`CACHE_ADDR`/`OBJECT_STORAGE_ENDPOINT` only when pointing at external/overridden endpoints.
- Production overrides: Provide production database and encryption secrets through chart secrets or an existing Secret where supported; override image tags, ingress, resources, and persistence.
- Source/license: Source is in `github.com/LerianStudio/helm`; license is Elastic License 2.0.

Helm chart for deploying the BC Correios plugin service.

## Install

```sh
helm repo add bitnami https://charts.bitnami.com/bitnami
helm dependency build ./charts/plugin-bc-correios
helm upgrade --install plugin-bc-correios ./charts/plugin-bc-correios \
  --namespace plugin-bc-correios --create-namespace \
  --values ./charts/plugin-bc-correios/values-template.yaml
```

If the migrations Job fails (for example the database was not reachable yet), fix the cause, delete the Job with `kubectl delete job -n plugin-bc-correios -l app.kubernetes.io/instance=plugin-bc-correios,app.kubernetes.io/component=migrations`, then run `helm upgrade` again.

## Required Configuration

- The chart applies the database migrations before the app serves traffic: a Job copies the SQL files from the app image (`/migrations`) and runs the `migrate/migrate` CLI (`bc-correios.migrations.*`; disable with `bc-correios.migrations.enabled: false` to run them yourself). The Job builds its database URL from the app's `POSTGRES_*` values, so a PostgreSQL password with URL-reserved characters must be URL-safe (the bundled subchart generates one that is).
- The bundled Valkey runs with `--maxmemory-policy noeviction`: the app keeps idempotency records and rate-limit counters there, and requires an external Valkey to use the same policy with an explicit memory ceiling.
- HTTP rate limiting runs on Valkey and is on by default: `RATE_LIMIT_ENABLED: "true"` (the limiter is off unless it is `"true"`). The limiter refuses requests when Valkey cannot decide. Set `RATE_LIMIT_ENABLED` in `bc-correios.configmap`.
- The application image `ghcr.io/lerianstudio/plugin-bc-correios` is private: set `bc-correios.imagePullSecrets` to a Secret that can pull it.
- Set `ENCRYPTION_KEY` before install; unless `ENV_NAME` is `development` it must be exactly 32 bytes. The bundled PostgreSQL and Valkey passwords are auto-generated by their subcharts and read via `secretKeyRef`; to pin them, set `postgresql.auth.*` / `valkey.auth.*` or supply `postgresql.auth.existingSecret` / `valkey.auth.existingSecret`. For an external Valkey with authentication, set `bc-correios.secrets.CACHE_PASSWORD`, or `valkey.auth.existingSecret` (with `valkey.auth.existingSecretPasswordKey`, default `valkey-password`), which takes precedence and is read via `secretKeyRef`.
- Set `bc-correios.configmap.STREAMING_BROKERS` to the Kafka-API broker list (for example `broker.example.com:9092`): the app refuses to start without it, and the chart refuses to render it blank (unless `bc-correios.useExistingSecret` supplies it). The app publishes to the topic `lerian.streaming.br-correios` and its dead-letter topic `lerian.streaming.br-correios.dlq`; provision both. An unreachable broker does not stop the app: events wait in the database outbox. For TLS set `STREAMING_TLS_ENABLED: "true"`; for SASL set `STREAMING_SASL_MECHANISM`, `STREAMING_SASL_USERNAME` and `bc-correios.secrets.STREAMING_SASL_PASSWORD` together with `STREAMING_TLS_ENABLED: "true"`, because the app refuses SASL over plaintext. Set `STREAMING_CLIENT_ID` and `STREAMING_TLS_CA_CERT` (base64-encoded PEM) through `bc-correios.extraEnvVars`.
- The default install has plugin auth on: `PLUGIN_AUTH_ENABLED: "true"`, authorizing requests against the Access Manager at `PLUGIN_AUTH_ADDRESS` (default `http://plugin-access-manager-auth.midaz-plugins.svc.cluster.local:4000`). The app reads `PLUGIN_AUTH_ADDRESS` and lib-auth reads `PLUGIN_AUTH_HOST`, so the chart renders both with one value; `PLUGIN_AUTH_HOST` in `bc-correios.configmap` takes precedence over `PLUGIN_AUTH_ADDRESS`. With `bc-correios.useExistingSecret`, the chart renders no `PLUGIN_AUTH_HOST` unless `bc-correios.configmap.PLUGIN_AUTH_HOST` is set, so put it in that Secret or in `configmap`. `ENV_NAME` is the app's environment and the chart renders it as `production` unless you set it. The app requires a license (`LICENSE_KEY`) and a streaming broker in every environment. Unless `ENV_NAME` is `development`, it also refuses `POSTGRES_SSLMODE: "disable"`, `ALLOWED_ORIGINS` empty or `*`, an `ENCRYPTION_KEY` that is not exactly 32 bytes and `FEATURE_AUDIT_ENABLED: "false"`. It refuses `PLUGIN_AUTH_ENABLED: "false"` unless `ENV_NAME` is one of `development`, `develop`, `dev`, `local` or `test`. The chart refuses to render the license or the broker blank, `POSTGRES_SSLMODE: "disable"` and `ALLOWED_ORIGINS` empty or `*` in the same cases. The bundled PostgreSQL has TLS off: set `postgresql.tls.enabled` and `postgresql.tls.autoGenerated` to `true`, or use an external PostgreSQL with TLS. For a development install set `ENV_NAME: "development"`.
- Review `bc-correios.configmap` for service URLs, telemetry, and plugin runtime settings.
- Prefer `bc-correios.useExistingSecret` when production secrets are managed outside Helm.

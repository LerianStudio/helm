  DEPLOYMENT MODE

  Servers: 1  =>  SINGLE-NODE, NON-HA (intentional "facilitator" default).

             Resilience is delegated to lib-service-discovery's DynamicResolver
             (last-known-good cache). For real HA, scale to an ODD count:

{{- else }}

--------------------------------------------------------------------------------
  SD_ADDRESS for lib-service-discovery
--------------------------------------------------------------------------------
The library talks to the Consul HTTP API on the in-cluster ClusterIP Service.
{{- /* Resolve the upstream Consul resource prefix exactly as the subchart does:
   fullnameOverride, then global.name, then "<release>-<nameOverride|consul>".
   The server Service is "<prefix>-server", so a custom name resolves correctly. */}}
{{- $consul := .Values.consul | default dict }}
{{- $cglobal := $consul.global | default dict }}
{{- $prefix := $consul.fullnameOverride | default $cglobal.name | default (printf "%s-%s" .Release.Name ($consul.nameOverride | default "consul")) | trunc 63 | trimSuffix "-" }}
{{- $server := printf "%s-server" $prefix }}

{{- if $cglobal.tls.enabled }}
  TLS is ENABLED -> use the HTTPS port (8501):

    SD_ADDRESS=https://{{ $server }}.{{ .Release.Namespace }}.svc:8501

  Provide the CA generated by the tls-init Job to the library so it can verify
  the server certificate.
{{- else }}
  TLS is DISABLED -> use the HTTP port (8500):

    SD_ADDRESS={{ $server }}.{{ .Release.Namespace }}.svc:8500
{{- end }}

Confirm the exact Service name/ports with:

  kubectl get svc -n {{ .Release.Namespace }} {{ $server }}

--------------------------------------------------------------------------------
  ACL BOOTSTRAP TOKEN
--------------------------------------------------------------------------------
{{- if .Values.consul.global.acls.manageSystemACLs }}
The chart manages the ACL system and stores the **bootstrap** token — a
full-access, ADMINISTRATOR-ONLY credential — in a Kubernetes Secret:

  kubectl get secret -n {{ .Release.Namespace }} {{ $prefix }}-bootstrap-acl-token \
    -o jsonpath='{.data.token}' | base64 -d ; echo

Do NOT give the bootstrap token to application workloads — it can manage ACLs,
KV and the whole cluster. Use it ONCE, as an operator, to mint a least-privilege
service-discovery token for lib-service-discovery:

  # 1) Policy — PER WORKLOAD: write ONLY its own service, read the rest to
  #    discover. A blanket service_prefix "" write would let any holder overwrite
  #    or deregister every service — not least-privilege.
  cat > sd-<svc>.hcl <<'EOF'
  service "<svc>"   { policy = "write" }   # register/update ONLY this workload's service
  service_prefix "" { policy = "read"  }   # discover other services
  node_prefix    "" { policy = "read"  }   # read node health for resolution
  EOF
  # 2) One policy + token PER workload (CONSUL_HTTP_TOKEN = the bootstrap token):
  consul acl policy create -name sd-<svc> -rules @sd-<svc>.hcl
  consul acl token create  -description sd-<svc> \
      -policy-name sd-<svc> -format=json | jq -r .SecretID

Put each SecretID in that workload's own Secret and pass it as SD_TOKEN — one
per service, rotatable/revocable independently of the bootstrap token. See
https://developer.hashicorp.com/consul/docs/secure/acl/token/service
{{- else }}
ACL management is DISABLED (consul.global.acls.manageSystemACLs=false).
No bootstrap token is created; the library needs no token. Enable ACLs for any
non-dev environment.
{{- end }}

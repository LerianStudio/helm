| `common.configmap` | object | `{}` | Shared (common) application config for BOTH the manager and worker surfaces. Set common.configmap.<KEY> here to override any shared key; add any other key and it flows through as-is. |
| `datastores` | object | `{}` | Dedicated datastore masks for THIS release (override global.datastores). Both the manager and worker surfaces share these connections. Sub-keys (each host/port/user/ssl): mongo:    { host, port, user }         # MongoDB (report store + tenant cache) redis:    { host }                     # Valkey/Redis (host carries host:port) broker:   { host, port }               # RabbitMQ (the generate-report queue) postgres: { host, port, user, ssl }    # external midaz datasource (direct-query mode) The native common.configmap.<KEY> still wins over these; these win over global.datastores. |
| `secrets.MONGO_PASSWORD` | string | `""` | Credentials for the reporter workloads.  useExistingSecret path (recommended for production): set `manager.useExistingSecret: true` + `manager.existingSecretName: <name>` (and the same for `worker`) and provide a Kubernetes Secret whose KEYS match the env-var names below. The workloads mount it via `envFrom.secretRef`, so every credential is referenceable from your own secret manager without ever templating a value here. Required keys in that existing Secret: - RABBITMQ_DEFAULT_USER / RABBITMQ_DEFAULT_PASS  (broker credentials) - RABBITMQ_ERLANG_COOKIE                          (bundled broker only; stable value) - DATASOURCE_ONBOARDING_PASSWORD                  (only when a direct datasource is configured) - OBJECT_STORAGE_ACCESS_KEY_ID / OBJECT_STORAGE_SECRET_KEY (external S3 only) - MONGO_PASSWORD                                  (external MongoDB only; bundled is single-sourced) - APP_ENC_KEY                                     (fetcher integration; base64 32-byte key)  Chart-managed path (default): leave `useExistingSecret: false` and set the values below; the chart renders them into the `<manager.name>` Secret.  MONGO_PASSWORD is single-sourced from the Bitnami mongodb subchart Secret (<release>-mongodb, key mongodb-root-password) and read via secretKeyRef — leave empty with the bundled subchart; only set for an external MongoDB without mongodb.auth.existingSecret. See docs/helm-chart-standard.md "Single-Source Infra Secrets". |
| `secrets.SD_TOKEN` | string | `""` | Service discovery (lib-service-discovery) Consul ACL token. Operator-provided; only needed when common.configmap.SD_ENABLED=true and the Consul server enforces ACLs. Left empty (and rendered empty) otherwise. |
| `seaweedfs.global` | object | `{}` | Subchart-wide settings. createClusterRole is disabled by default: the bundled seaweedfs chart otherwise creates a FIXED-NAME cluster-scoped ClusterRole ("<serviceAccountName>-rw-cr") and ClusterRoleBinding that collide when more than one release is installed on the same cluster (different namespaces). The role only backs an optional pod-deletion hack after volume migration, so it is off by default. To re-enable, set createClusterRole=true AND a release-unique serviceAccountName. |

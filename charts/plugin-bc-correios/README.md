# plugin-bc-correios Helm Chart

## Chart Contract

- Chart type: `single-service`
- Required secrets: `bc-correios.secrets.RABBITMQ_PASS`, `RABBITMQ_URL`, and `ENCRYPTION_KEY`. The PostgreSQL password is **not** operator-provided with the bundled subchart: the Bitnami `postgresql` subchart auto-generates it into the `<release>-postgresql` Secret (key `password`) and the app reads it via `secretKeyRef`. Set `bc-correios.secrets.POSTGRES_PASSWORD` only for an external PostgreSQL (`postgresql.external=true`) without `postgresql.auth.existingSecret`.
- Dependency notes: Uses local PostgreSQL, RabbitMQ, and Valkey dependency charts (plus an inline SeaweedFS deployment) unless external services are configured. The in-cluster PostgreSQL, RabbitMQ, Valkey, and object-storage hosts are derived automatically (collapse-aware), so any release name works; set the corresponding `bc-correios.configmap.*_HOST`/`CACHE_ADDR`/`OBJECT_STORAGE_ENDPOINT` only when pointing at external/overridden endpoints.
- Production overrides: Provide production database, RabbitMQ, and encryption secrets through chart secrets or an existing Secret where supported; override image tags, ingress, resources, and persistence.
- Source/license: Source is in `github.com/LerianStudio/helm`; license is Elastic License 2.0.

Helm chart for deploying the BC Correios plugin service.

## Install

```sh
helm dependency build ./charts/plugin-bc-correios
helm upgrade --install plugin-bc-correios ./charts/plugin-bc-correios \
  --namespace plugin-bc-correios --create-namespace \
  --values ./charts/plugin-bc-correios/values-template.yaml
```

## Required Configuration

- Set the required RabbitMQ secrets (`RABBITMQ_PASS`, `RABBITMQ_URL`) and `ENCRYPTION_KEY` before install. The bundled PostgreSQL and Valkey passwords are auto-generated by their subcharts and read via `secretKeyRef`; to pin them, set `postgresql.auth.*` / `valkey.auth.*` or supply `postgresql.auth.existingSecret` / `valkey.auth.existingSecret`. For an external Valkey with authentication, set `bc-correios.secrets.CACHE_PASSWORD`, or `valkey.auth.existingSecret` (with `valkey.auth.existingSecretPasswordKey`, default `valkey-password`), which takes precedence and is read via `secretKeyRef`.
- The bundled RabbitMQ is started without a default user or password, its definitions file declares no users, and its data volume is an `emptyDir` (`rabbitmq.persistence.size` is not a key of the subchart and has no effect). Create the broker account used in `RABBITMQ_URL` yourself, or use an external broker. The RabbitMQ bootstrap Job (`global.externalRabbitmqDefinitions.enabled`) only imports exchanges, queues, and bindings; it does not create users.
- The default install is production with plugin auth on: `bc-correios.configmap.ENV_NAME: "production"` and `PLUGIN_AUTH_ENABLED: "true"`, authorizing every request against the Access Manager at `PLUGIN_AUTH_ADDRESS` (default `http://plugin-access-manager-auth.midaz-plugins.svc.cluster.local:4000`). Outside `ENV_NAME: "development"` the app also refuses `POSTGRES_SSLMODE: "disable"`, `ALLOWED_ORIGINS: "*"` and an `ENCRYPTION_KEY` that is not exactly 32 bytes. `LICENSE_KEY` is required in every environment, development included. For a development install without an Access Manager, set `ENV_NAME: "development"` and `PLUGIN_AUTH_ENABLED: "false"`; the app refuses auth off unless `ENV_NAME` is development-class (`development`, `develop`, `dev`, `local`, `test`).
- Review `bc-correios.configmap` for service URLs, telemetry, and plugin runtime settings.
- Prefer `bc-correios.useExistingSecret` when production secrets are managed outside Helm.

## Dependencies

This chart depends on PostgreSQL, RabbitMQ, and Valkey subcharts. Run `helm dependency build` before rendering or installing from a local checkout.
